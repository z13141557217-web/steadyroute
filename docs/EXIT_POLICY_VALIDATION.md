独立真实 Mihomo v1.19.33 / Python3.9：旧规则集经另一个组建立长连接，重载为固定目标后旧 ID 仍存在、旧响应仍来自原测试出口；新请求链经过锁定目标；旧响应自然完成后显示 `no_sessions`，只核实规则，不冒充会话固定。新增其他国家和 DIRECT 旧连接跨重载用例，保留目标异常、断连、移除、空集、可用备用/DIRECT控制路径及变异反例。当前共9项内核专项，最终完整门禁计数与提交对应关系以审阅请求及本地逐项验收表为准。

后端矩阵覆盖目标一致、同国异节点、其他国家、DIRECT、已知AI缺链/仅组链、正常/异常/普通连接混合、离线、抓取失败、合法空快照、过期与未来时钟异常。foreign/unknown存在、无活动或证据无效时均不绿。设置快照和看板逐字段比较同一结论；缓存过期投影无控制器读取，快检生成时间改变但连接时间不变。

本轮完整门禁508项：507通过、1项因平台条件跳过，9项真实内核专项全部执行；敏感信息扫描通过。浏览器设置10场景、看板10场景，其他出口/未知/无效证据的错误绿色次数为0；另验证页面API读取失败后撤下旧绿色结论。曾有一次隔离专项出现本地监听端口拒绝连接，失败记录保留；测试启动/重载就绪条件补为控制器及数据监听均可用，不改变路由断言，随后专项和完整门禁通过。最终提交前门禁与远端CI另按精确提交核对。

历史现场数据本地回放也由 rc.1 的“0 条/固定”变为 rc.2 的“1 条/等待结束”。这证明核验漏报已修复，不证明截图中的某个公网 IP 与某条历史连接是一一对应，也不证明供应商公网 IP 地区。现有元数据不足时无法完整归类，零条不是全流量验证。
