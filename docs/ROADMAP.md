# 路线图与迭代计划

更新时间：2026-09-22。按风险和验收门槛排序，不以日历日期强推上线。
版本号表达兼容性与范围；合并 PR、创建 tag、发布 GitHub Release 和部署生产各需独立确认。

## 已交付的基线

- v0.1.0：受管源码、CI、初始测试和文档。
- v0.2.0：原子部署、备份、校验和回滚。
- v0.3.0：统一状态契约、状态机、有界事件和只读 API。
- v0.4.0：动态候选发现与生命周期，**仅影子运行**。
- v0.4.1：Clash Verge 2.5.4 控制面兼容和组选择安全回放。
- v0.4.2：隐藏内部发现组、最多一小时人工偏好；仍仅影子运行。

详细事实和已知限制见[版本历史](VERSION_HISTORY.md)。

## 当前门槛：v0.4.2 观察

观察至少 12–24 小时，覆盖一次**真实订阅刷新**。记录刷新前后候选新增/消失、
`hidden`、当前线路、事件、内存、主/错误日志和控制器恢复。普通探测成功、
`generation` 不变或持续运行时间本身，都不能替代订阅刷新证据。
若发现隐私/跨区/直连风险，先保护生产并回滚，再讨论后续计划。

## v0.5.0：运维可观测性与只读版本历史

这是一版兼容的新看板能力，因此按现有语义化规则使用 **MINOR**，
不挤进 PATCH。它不改变动态候选是否参与实际选路，也不自动重写 Clash Verge 配置。

**范围：**

1. [Issue #3](https://github.com/z13141557217-web/steadyroute/issues/3)：主日志和错误日志按大小/数量轮换并明确总量上限；测速明细限频，保留故障和状态转换；仅屏蔽浏览器/看板客户端断开导致的无害写响应错误。
2. 看板只读“更新日志”入口：显示实时运行版本、历史版本的实际变更、发布状态、已知限制和回滚信息。详细内容以[版本历史](VERSION_HISTORY.md)为单一维护源，构建时打包本地只读数据，页面加载不访问 GitHub、不触发测速或切线。验收见[设计规范](RELEASE_NOTES_VIEW_SPEC.md)。
3. 与本版范围直接相关的日志、API、看板、发布包和回归测试；必要时更新文档与迁移说明。

**不在范围：**动态候选正式接管、自动写入升级后的 Clash Verge 配置、网页端控制线路、完整趋势/历史数据库、全量视觉重设计。完整看板改造仍由
[Issue #5](https://github.com/z13141557217-web/steadyroute/issues/5) 另行拆分。

**发布门槛：**v0.4.2 的影子观察结论明确；日志上限和保留期测试通过；
异常日志不被误吞；旧状态 API 兼容；版本历史在离线、本机、旧包/新包和缺失数据时可读且不产生网络或控制器写操作；
发布包校验、候选看板验收和回滚演练通过。合并/发布仍须用户验收。

## 条件目标：v0.6.0 动态接管

`v0.6.0` 只是把原先占用 v0.5.0 的高风险功能移到独立版本的**暂定编号**，
不是发布日期或默认授权。进入开发/发布前须：

- 证明 v0.4.x 影子观察覆盖真实订阅刷新，候选增删改名与空组安全；
- 完成[Issue #6](https://github.com/z13141557217-web/steadyroute/issues/6) 假 Mihomo Unix socket 集成测试、故障注入与回滚；
- 明确候选配置、手动偏好、无损回优和跨区/DIRECT 禁止的完整行为边界；
- 测量 CPU、内存、测速请求量及状态新鲜度，满足既定资源门槛；
- 用户单独审批 `shadow → active`，不能因版本号、PR 合并或升级自动接管。

其他待办继续按[产品待办](BACKLOG.md)排序；任何版本都须遵守
[发布流程](RELEASE.md)与[项目状态](PROJECT_STATUS.md)。
