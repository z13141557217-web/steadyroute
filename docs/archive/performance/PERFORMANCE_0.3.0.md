# v0.3.0 状态契约性能对比

日期：2026-09-20  
平台：macOS 系统 Python 3.9  
方法：分别在独立 Python 进程中导入 `1e7ef80` 与当前候选，使用相同的空状态和
`HTTPServer`，绑定本机回环随机端口。缓存预先生成；测量一次 GET、空闲一秒的进程
CPU、100 次串行 `/api/status` GET 和进程峰值 RSS。未读取 Mihomo、未使用生产状态、
未修改或部署生产。

| 指标 | v0.2.0 / `1e7ef80` | v0.3.0 候选 | 差异 |
|---|---:|---:|---:|
| 峰值 RSS | 19.27 MB | 19.41 MB | +0.14 MB（+0.7%） |
| 空闲 CPU | 0.010% | 0.015% | +0.005 个百分点 |
| 单次兼容 API | 4.351 ms | 3.604 ms | -0.747 ms |
| 100 次兼容 API 总耗时 | 33.228 ms | 33.035 ms | -0.193 ms |

| 100 次 p95 | 0.472 ms | 0.614 ms | +0.142 ms |
| 单次 `/api/v1/status` | 不适用 | 0.346 ms | 新接口 |

候选兼容响应为 2,457 bytes，新接口为 3,236 bytes。两者均在周期结束时一次编码，
100 次请求只复制缓存字节，没有探测、连接扫描或状态转换。RSS 增量小于 1%，空闲 CPU
差异处于测量噪声，100 次总耗时没有回退；未发现需要用额外常驻内存、进程或依赖
换取性能的理由。

生产未部署，因此本文件不声称生产指标已经改变。管理窗口若批准发布，应按
`docs/RELEASE.md` 在同一机器再次测量真实常驻进程；若 RSS、空闲 CPU 或接口延迟明显
回退，立即使用完整备份回滚 v0.2.0。
