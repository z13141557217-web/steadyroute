# 项目章程

## 背景与目标

稳航已经具备可用的自动选路能力，但此前直接在生产目录开发，没有 Git、正式版本、发布门禁和系统化回滚。本项目的目标是把它治理成一个可重复开发、验证、发布和恢复的本机产品。

## 用户与干系人

| 角色 | 职责 |
|---|---|
| 产品所有者 | 决定路由策略、风险偏好和发布验收 |
| Codex 开发代理 | 设计、实现、测试、文档与发布准备 |
| 稳航后台服务 | 执行已发布版本，不承担开发职责 |
| Clash Verge/Mihomo | 提供流量分流、代理组和控制 API |

## 范围

### In Scope

- 后端选路、状态管理和本地 HTTP API。
- 本地只读数据看板。
- Clash Verge 代理组增强配置。
- 日志、运行状态和故障诊断。
- Git、版本、测试、构建、发布、回滚和备份。
- 安全、隐私、性能和长期维护。

### Out of Scope

- 远程公网访问看板。
- 云端控制面或外部数据库。
- 自动购买、更新或管理机场订阅。
- 自动操作第三方账号。
- 未经批准的新常驻服务和运行时依赖。

## 核心成功指标

| 指标 | 目标 |
|---|---|
| 生产变更可追溯率 | 100% 对应 Git commit 和版本 |
| 发布前自动检查通过率 | 100% |
| 失败发布可回滚时间 | 5 分钟以内 |
| 生产配置泄密 | 0 |
| 状态与日志无限增长 | 0 |
| 空闲 CPU | 接近 0% |
| 常驻内存 | 不因治理工作显著回退 |

## 验收定义

功能只有同时满足代码、测试、文档、变更日志、版本影响、发布验证和回滚方案时才算完成。
