# 看板只读更新日志：v0.5.0 功能规范

状态：已规划，**尚未开发**。本文件只定义下一版本的范围和验收，不改当前看板或生产。
开发跟踪：[Issue #16](https://github.com/z13141557217-web/steadyroute/issues/16)。

## 用户问题与目标

用户现在需要到 GitHub 查多个 tag、PR 和文档，才能弄清“当前运行的是哪一版、
每版实际改了什么、哪些仍只是影子功能、可如何回滚”。看板应在本机离线、
不改变任何线路的前提下给出可信答案。

## 数据来源与边界

- 当前运行版本只取正在运行进程的状态 API；若离线、过期或缺字段，显示“无法确认运行版本”，不得把最新历史版本冒充当前版本。
- 历史版本详情以[VERSION_HISTORY.md](VERSION_HISTORY.md)为人工维护的唯一事实源；构建发布包时生成/打包本地只读数据。构建检查必须验证必填字段、版本排序、tag 对应关系和本地链接有效；不依赖联网检查外部链接，也不允许在页面或另一份 JSON 中手工复制维护。
- 展示 Git tag、GitHub Release、生产部署三种不同事实：有 tag 不等于有 Release，有 Release 不等于已部署。无法核实的状态显示“未确认”。
- 页面加载和浏览版本历史只读本地缓存/静态包；不得访问 GitHub、订阅地址、Mihomo 测速 API，也不得向控制器发送写请求。
- 内容不得包含认证、订阅 URL、节点服务器地址或个人网络身份信息；可显示脱敏的版本、PR/Issue 编号、测试结论、限制、备份与回滚说明。

## 最小界面

1. 在现有看板提供明确的“更新日志”入口。打开后先显示“当前运行版本”和状态时间，再显示可浏览的历史版本列表。
2. 每版展开后按“实际改变 / 验收证据 / 已知限制 / 备份与回滚”阅读；动态发现是否仅影子运行必须直接写出，不能藏在笼统的“已完成”中。
3. 若运行版本和打包历史不匹配，显示“版本记录与运行版本不一致”，不静默套用最新条目；若记录缺失，给出空态而非报错白屏。
4. 保留现有看板的紧凑布局；桌面与窄窗口均可阅读，键盘可进入、展开和返回；用文字而不仅用颜色表示状态。

## 验收样例

- v0.4.2 运行、历史含 v0.4.2：当前标签准确，且明确“动态候选仅影子运行”。
- 离线断开 GitHub：内容仍完整可读，网络请求列表没有 GitHub/测速/切线请求。
- 状态 API 不可用、过期或版本缺失：显示“无法确认”，不把 v0.5.0 最新条目说成正在运行。
- 历史包比运行版本旧/新、历史数据缺项、非法版本排序：构建时报错或页面显式提示，不误导。
- 版本历史切换、展开/关闭和窄窗口测试不改变现有 API、代理组或探测周期。

这项功能单独验收后才能随 v0.5.0 发布；本规范不是发布授权。
