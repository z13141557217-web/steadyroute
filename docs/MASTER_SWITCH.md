# 稳航运行控制

设置顶部和看板的总开关同时显示已保存意愿和实际工作进程。所有停止操作先显示切换中，失败显示原因，不以未保存草稿替代实际状态。

| 操作 | 工作进程 | 控制页面 | 固定保护与资料 |
|---|---|---|---|
| 暂停工作进程，保留规则 | 等待在途事务后退出 | 保留，可再次启动 | 已写入规则保留；目标、设置、历史保留 |
| 停用并交还 Clash | 先停止 | 保留 | 预览后确认撤销当前订阅自己的分组/规则，解除固定保护；偏好及其他订阅记录保留 |
| 停止稳航.command | 先完成暂停 | 然后退出 | 规则保留，不宣称全部干预已撤销 |
| 启动稳航.command | 预览确认前不启动 | 独立打开 | 核对当前订阅与原目标，无自动换国或 DIRECT |

新安装先暂停；升级保留已有控制状态，首次引入总开关也先暂停并保留内核规则。登录时启动工作进程独立保存，只有上次允许运行且登录启动已开启，正常退出后下次登录才重新预览核对启动。显式暂停、崩溃或未完成的操作均不自动恢复。轻量控制页面可由启动项维持，不探测或自动修改内核。

暂停时可点击“核对下次启动目标”，从当前订阅与内核交集中的明确地区家宽叶子中手动选择，预览地区及目标变化并勾选确认。保存仅改下次启动偏好，不接管、不重载、不切节点。没有原目标时也可保留停用并补充原目标。不能用更新目标按钮绕过另一国家的授权；选择其他地区必须明确确认。

目标更新、启动和撤销都绑定预览时的订阅、源文件、扩展文件、运行配置及保存设置。期间变化会拒绝，重新预览。启动固定策略还检查当前选择；外部已换到其他节点时拒绝偷偷改回。订阅 provider、非标准节点格式无法可靠核对时宁可阻断，当前不会猜测 provider 节点归属。

工作进程与控制页面各持有独占锁，防止重复运行。共享操作屏障覆盖内核请求及设置/维护事务；关闭接单后仅允许已进入事务完成（包括回滚），等待排空才退出进程。超时保留禁止接单状态并显示未完成，重试暂停继续核对，不直接杀掉未知事务。工作进程不自动重启；控制进程消失时，工作进程检测父进程变化，关闭屏障并退出。屏障超时需要重试/人工核对，不能把页面离线当停止证据。

撤销按当前 profile 的可信记录操作；旧版已经把归属污染的记录需按 PROFILE_RECOVERY.md 用备份校正。仅看同名分组不能确定归属。操作前真实内核校验与当前配置核对，写入前备份，失败恢复。不要手工删除用户/订阅规则。不要强清连接来让状态变绿。

升级和回滚必须成套保存应用、control-state.json、配置、应用记录、Clash 文件及启动项；旧版不会遵守新控制状态。新后台含进程生命周期变化，原长期观察不重置也不充当本版本稳定性证据。
