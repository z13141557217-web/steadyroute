# 稳航 SteadyRoute 固定维护约束

- 后续修改不得无理由增加常驻内存；能不增加就不增加。
- 不新增运行时依赖、常驻进程或外部服务，除非用户明确批准。
- 每次性能或界面调整都要做修改前后 RSS、空闲 CPU 和本地接口响应测试。
- 出现资源回退时优先恢复旧实现，不用复杂度换取没有测量收益的“优化”。
- 看板继续使用同一进程、同一缓存快照和本机回环地址。
- UI 修改必须检查桌面布局、窄窗口适配、数字对齐、筛选逻辑和空状态。
- 活跃连接不得阻止优质线路恢复；性能回优只切换新请求，保留健康旧连接。
- 只有真实故障切换可以清理旧节点连接。
- 健康判断保持分层：基础连通、AI业务可达、短期窗口、长期窗口和节点隔离。
- 当前线路高频检测、备用线路低频轮询；异常时才临时扩大检测范围。
- 选路只有 `auto_lock` 一种方式；国家与家宽识别集中在 `regions.py`，新增国家不得在核心写业务分支。
- 只在锁定国家的家宽节点之间切换，任何情况下不跨国家、不用机房节点、不回落 DIRECT。
- 安装和升级不修改 Clash；只在用户于设置页确认后写入 Clash（自愈与每周同步只重新应用已确认的设置），每次都经内核校验、备份并可完整撤销。
- 只改 Clash Verge 扩展文件中稳航的标记区块，不碰用户自己的分组、规则和订阅；迁移时替换的旧稳航分组记录原文，撤销时原样放回。
- 仓库和发布包不得出现本机路径、用户名、真实节点名或订阅信息。
